## 主张：先问「谁在合法地读走明文」，再谈防线

安全产品最容易滑进的叙事是「防小偷偷硬盘」。顺着这条路走，最后往往只是又一个 AES-256 加密容器——而 AES-256 早就不是差异化，是红海标配。威胁建模的能力，不在于堆多少密码学名词，而在于**把「安全」这个形容词拆成具体的对手、场景和边界**。

MyLock 的做法是换一个问题：谁在你的电脑上，合法地、持续地把明文读走？

## 换一个问题，整份设计都变了

答案是云同步客户端、系统索引、桌面搜索、端侧 AI 助手、备份软件、屏幕快照。它们都经过用户授权，不会被防盗机制拦住，却会把 `.env`、合同扫描件、证件照悄悄复制进别人的索引和缓存。

围绕这个真正的对手，设计跟着重构：

- 产物从「一个加密文件」变成「一个静态密文目录」：盘上永远是密文，采集者拿走的是乱码。
- 解锁后映射成可写盘符只是「透明文件夹」形态，它**只在未解锁态真正安全**——这一点写在最显眼处，而不是藏在 FAQ。
- 「No Cloud / No AI / No Telemetry / No Account」不是营销词，而是架构属性：**没有上传通道**，所以不存在「承诺不上传」这种可被推翻的口头约定。

## 用三档边界代替「安全 / 不安全」的二元话术

威胁模型文档把结论分成三档，而不是含糊地说一句「安全」：

- **防得住**：静态密文、未解锁态、篡改与截断检测；
- **仅缓解**：解锁态的第二份明文、拒绝在同步根目录挂载；
- **防不住**：设备已攻陷、解锁态截屏、所有凭据同时丢失。

还有一个容易被忽略的架构事实——**零吊销**：改口令、换 Recovery Key 都不撤销旧凭据，真正吊销需要 `rotate-keys` 加物理销毁旧介质。把「现在还不能放心托付什么」写清楚，比多宣传一句「军工级加密」更能建立信任。这条判断后来直接演变成了作品页上的「诚实边界」一节。

## 合规与发布：把 NO-GO 说出来

到内核跑通、测试全绿时，上架准备的总判据依然是 **NO-GO**，因为四道外部闸门一道没过：A 第三方安全审计、B 律师签发、C 代码签名 + 可分发安装包、D 商店申报。内部密码学评审 ≠ 第三方审计；未签名的便携包和 debug 调试签名 APK ≠ 可分发正式版。

配套的是几条反直觉却必须说清的合规事实：零数据 App 仍要隐私政策、加密 ≠ 匿名化、开源 / 无网络不是出口管制豁免。证据分 A / A⁻ / B / C 级，B 级不进硬论据，NOT RETRIEVED 不臆造；依赖许可对外统一口径是「无 GPL 家族强 copyleft（已核验 0），但存在 MPL-2.0 文件级弱 copyleft」——绝不说「没有任何 copyleft」。

一条纪律贯穿全项目：**内核实现 ≠ 产品发布 ≠ 五端验收 ≠ 第三方审计**。看下面三条证据，就能核对这条主张是怎么落地的。
