## 全绿之后，判断却是否定的

到 M4 结束时，技术上该有的都有：Rust 内核 26/0、Android 真机 G4 一致、逐字节向量门禁、COW 写回、loopback WebDAV 挂载。但上架准备的总判据是 **NO-GO**，因为四道外部闸门全部未启动：

- **A 第三方安全审计**：内部密码学评审（三路对抗审阅、依据一手标准逐条裁定）≠ 第三方审计；
- **B 律师签发**：白皮书、隐私政策、BIS 通知模板都是草案，未经律师签发不得对外发布；
- **C 代码签名 + 可分发安装包**：桌面是未签名便携包，Android 是 debug 调试签名可侧载 APK，均不是可分发正式版；
- **D 商店申报**：未上架任何应用商店。

## 几个反直觉的合规事实

- **零数据 App 仍要隐私政策**：没有账号、没有服务端，不等于没有合规义务；
- **加密 ≠ 匿名化**：密文仍可能通过形状、元数据被关联；
- **开源 / 无网络不是出口管制豁免**：自研 XChaCha20-Poly1305 属 non-standard cryptography，公开源码不自动豁免 EAR / 欧盟两用物项管制。

## 依赖许可的诚实口径

第一方 crate 是 `MIT OR Apache-2.0`。用 `cargo fetch --locked` 覆盖 613 个包、把「不可核验」从 179 降到 0，生成 148 KB 的 `THIRD_PARTY_NOTICES.md`。对外统一措辞是：**无 GPL 家族强 copyleft（已核验 0），但存在 MPL-2.0 文件级弱 copyleft**——绝不说「没有任何 copyleft」。像 `r-efi 5.3.0/6.0.0` 里 LGPL-2.1-or-later 的 OR 选项只存在于 UEFI target，对目标平台不参与编译，这种细节要在报告里逐条标清。

## 一条贯穿全项目的纪律

证据分 A / A⁻ / B / C 级：B 级不进硬论据，NOT RETRIEVED 不臆造。全程守住一句话——**内核实现 ≠ 产品发布 ≠ 五端验收 ≠ 第三方审计**。

所以作品页和 README 都用同样的口径：alpha 内测、未经审计、未签名、请勿存放唯一副本。把「现在还不能放心托付什么」写清楚，正是这个项目建立信任的方式。
