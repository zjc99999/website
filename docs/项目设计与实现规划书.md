## 1. 立项基线（决策已锁定）

### 1.1 一句话目标

用 2~3 周搭出一个**我自己每天愿意往里写东西**的静态个人商业主页：访客 3 秒看懂我是谁、能帮我什么、下一步点哪；我用 `git push` 就能发布创作记录；站点自带把流量变成可跟进线索的最小闭环。

### 1.2 用户决策（m00079 原文意图）

> 「看了你写的文档，分析的有理有据，所以我接受你 Q1-Q10 的所有建议，先从自用、简单逻辑入手，使用中再图进一步发展。据此，你写一个项目设计与实现规划书，然后就可以逐步的推荐执行了。」

### 2.3 Astro 7 官方 API 事实核验（已核验，来自官方仓库原始文档）

来源：[Content collections 原始文档](https://raw.githubusercontent.com/withastro/docs/main/src/content/docs/en/guides/content-collections.mdx)、[Upgrade to Astro v7 原始文档](https://raw.githubusercontent.com/withastro/docs/main/src/content/docs/en/guides/upgrade-to/v7.mdx)、[Astro 官方文档目录](https://docs.astro.build/en/guides/content-collections/)。

1. 内容集合配置文件是 **`src/content.config.ts`**（`.js`/`.mjs` 亦可），不是旧版的 `src/content/config.ts`。
2. 每个集合必须有 `loader`，本地文件用 `glob({ base, pattern })` 或 `file()`；`glob()` 自动按文件名生成 URL 友好的 `id`，frontmatter 写 `slug` 可覆盖自定义 ID。
3. Schema 用 `import { z } from 'astro/zod'`（Astro 对 Zod 4 的再导出），支持 `.parse()` / `.transform()` / `.refine()`；`image().refine()` 不支持。
4. 跨集合引用用 `reference('collection')`，返回 `{ collection, id }`，配 `getEntry()` / `getEntries()` 查询。**M3 探针更正**：`reference()` 仅提供类型/自动补全与 IDE 校验，**不做目标条目存在性校验**（指向不存在的 id 仍能 build 通过）；存在性必须由业务代码在构建期保证，本项目由 `src/lib/evidence.ts` 的 `resolveEvidenceList()` + `scripts/verify-hard-rules.mjs` E4-c 实现。
5. 静态路由用 `getStaticPaths()` + `getCollection()`，正文渲染用 `render(entry)` 的 `<Content />`。
6. 过滤草稿：`getCollection('log', ({ data }) => import.meta.env.PROD ? data.status !== 'draft' : true)`。
7. TypeScript 模板 `astro/tsconfigs/strict` 已内置 `strictNullChecks` / `allowJs`，无需手写。
8. Astro 自动生成 `.astro/collections/<name>.schema.json`，可给编辑器做 JSON/YAML frontmatter 智能提示。
9. **v7 破坏性变更**：升级 Vite 8；Rust 编译器成为唯一编译器（**未闭合标签直接报错**、不再自动纠正非法 HTML 嵌套如 `<p><div>`）；`compressHTML` 默认由 `true` 变为 `'jsx'`（行内元素间空格会被吞，需 `{" "}` 或设回 `compressHTML: true`）；`src/fetch.ts` 成为高级路由保留文件名；默认 Markdown 处理器改为 **Sätteri**（remark/rehype 插件需装 `@astrojs/markdown-remark` 并显式 `markdown: { processor: unified() }`）；`@astrojs/db` 已移除；`experimental.logger / queuedRendering / rustCompiler / advancedRouting / cache / routeRules` 转为顶层稳定配置。
10. 现代运行时模块存在：`astro:content`、`astro:zod`、`astro:assets`、`astro:i18n`、`astro:actions`；适配器有 Cloudflare / Vercel / Node / Netlify；部署指南含 [EdgeOne Pages](https://docs.astro.build/en/guides/deploy/edgeone-pages/)（国内备选印证）。

## 3. 工程约束（实现层硬规则）

| # | 约束 | 落地手段 |
|---|---|---|
| E1 | 读路径全静态 | `output` 不显式声明（Astro 默认 static）；产物 `dist/` 纯 HTML/CSS/资源；**不在读路径上放任何 fetch / 数据库 / 会话** |
| E2 | 错误拦在构建期 | Zod schema + `astro check` + `astro build` 三步在 CI 中串行，任一失败即阻断部署 |
| E3 | 内容主权 | 所有内容明文存 `src/content/**/*.{md,mdx}`，Git 版本史即备份；`scripts/export-all.mjs` 一键导出全量内容与订阅者 CSV（R1 先把脚本位和格式定好） |
| E4 | 两条构建期硬校验 | `capability.evidence_ids.length > 0`、`case_study.consent === true`（Zod `.refine()`；违反即 build 失败） |
| E5 | 组织化字段当天埋 | 所有集合 frontmatter 从 R1 起带 `workspace_id` / `owner_member_id`（恒定单值），R3 不需迁移语义 |
| E6 | 首屏预算制 | 身份 1 / 价值 1 / 作品卡 ≤3 / 主 CTA 1 / 次 CTA 1 / 导航 ≤5 / 社交外链 ≤3（页脚）；禁长段落、技能标签云、全量日志、动效轮播、第三方聊天挂件、cookie 横幅 |
| E7 | 性能预算 | 首屏 JS ≤50KB、LCP <1.5s(4G)、CLS <0.1、Lighthouse ≥95 |
| E8 | 隐私 | 事件不含明文 PII（仅 `anon_hash`）；订阅显式同意 + 来源留痕 + 一键退订；第三方脚本清单 + 隐私政策页 |
| E9 | 可替换性 | 每个外部服务通过 `src/lib/` 薄封装接入，替换时只改一处（概要设计 6.4） |
| E10 | 简单逻辑优先 | 能用静态 HTML 解决的不引 JS；能用第三方托管解决的不自建服务；R1 不引数据库 |
| E11 | 弃更是头号风险 | `scripts/new-log.mjs` 必须让「写一条 100 字短记录 → push」≤2 分钟；`/log` 支持 6 种短类型 |
| E12 | 全部可逆 | 无数据库、无迁移；`pnpm-lock.yaml` 入库；任何步骤可 `git revert` 回到上一步 |

### 5.2 `src/content.config.ts` 骨架（M2 实现，示意）

import { glob, file } from 'astro/loaders';
import { z } from 'astro/zod';

// R1 起固定单值，R3 无需迁移语义 (E5)
const OWNER = z.literal('me');

const base = {
  workspace_id: WORKSPACE,
  owner_member_id: OWNER,
  title: z.string().min(1),
  summary: z.string().min(1),
  status: z.enum(['draft', 'scheduled', 'published']).default('draft'),
  visibility: z.enum(['public', 'unlisted', 'private']).default('public'),
  published_at: z.coerce.date(),
  updated_at: z.coerce.date().optional(),
  tags: z.array(z.string()).default([]),
  locale: z.enum(['zh-CN', 'en']).default('zh-CN'),
  seo: z.object({
    title: z.string().optional(),
    description: z.string().optional(),
    og: z.string().optional(),
  }).default({}),
};

const products = defineCollection({
  loader: glob({ base: './src/content/products', pattern: '**/*.{md,mdx}' }),
  schema: z.object({
    ...base,
    tagline: z.string().min(1),
    status_product: z.enum(['idea', 'building', 'live', 'archived']),
    url: z.string().optional(),
    repo_url: z.string().optional(),
    cover: z.string().optional(),
    metrics: z.record(z.string(), z.union([z.string(), z.number()])).default({}),
    launch_date: z.coerce.date().optional(),
    featured: z.boolean().default(false),
    order: z.number().default(0),

});

const log = defineCollection({

  schema: z.object({
    ...base,

    related_ids: z.array(reference('log')).default([]),
    reading_time: z.number().optional(),

});

const capabilities = defineCollection({
  loader: glob({ base: './src/content/capabilities', pattern: '**/*.md' }),

  schema: z.object({
    ...base,
    category: z.string(),
    statement: z.string().min(1),
    evidence_ids: z.array(z.string()).min(1),

});

const cases = defineCollection({

> **更正版（2026-11-12，M3 探针实测）**：上面这段示意仅用于表达结构，不是 Astro 7 的实际行为，也不是 M2 落地代码的逐字副本。
> ① `reference()` **只提供 TypeScript 类型与自动补全，不做跨集合存在性校验**——M3 探针写入 `product_id: does-not-exist-xyz` 后 `astro build` 仍 `EXIT=0`。因此「证据链」不是靠 `reference()` 保证，而是由 `src/lib/evidence.ts` 的 `resolveEvidenceList()` 在**构建期**解析每个 `evidence_id`（目标不存在即 throw、中断 build），并由 `scripts/verify-hard-rules.mjs` 的 E4-c 用例回归。原先「正好把证据链从约定变成编译期事实」一句是错的，已作废。
> ② 落地实现与示意的差异（以 `src/content.config.ts` 为准）：作品状态字段改名 `stage`（避免 frontmatter 出现两个 `status`）；`base.status` 收敛为 `draft | published` 两级（R1 无发布调度器）；错误提示改用 Zod 4 的 `{ error: '...' }` 语法；`file()` loader 要求 `profile.json` 为数组且每条带唯一 `id`。详见文末「Step 2 / M2 执行期新增事实」。
> ③ `base` 中的 `status` / `visibility` 统一驱动 `getCollection` 的过滤（`import.meta.env.PROD` 时排除 `draft` 与 `private`，见 `src/lib/constants.ts` 的 `isPublicProd()`）。

**执行期新增事实与决策（登记备查）**：

1. **Astro 7 硬事实**：内容集合配置在 `src/content.config.ts`（非旧 `src/content/config.ts`）；每个集合必须有 `loader`；`file()` loader 要求 JSON 为**数组且每条带唯一 `id`**（`glob()` 才按文件名自动生成 id）；`reference()` 把值转成 `{collection,id}`；schema 校验失败抛 `InvalidContentEntryDataError`。已据此把 `profile.json` 从单对象改成 `[{"id":"me",...}]`。
2. **Zod 4 语法**：Astro 7 用的是 `astro/zod`（Zod 4 再导出），自定义错误必须写 `z.string().min(1, { error: '...' })` / `.refine(fn, { error: '...' })` / `z.literal(true, { error: '...' })`；旧式第二参数字符串位置参数不生效。两条硬校验已用新语法落地并通过回归测试。
3. **偏离示意 D-1（记录不影响语义）**：规划书 §5.2 示意里作品状态字段名写作 `status_product`，实现改为 **`stage`**，理由：避免与 `base.status`（`draft|scheduled|published`）在同一 frontmatter 出现两个 `status` 造成混淆；取值不变（`idea|building|live|archived`）。`workspace_id`/`owner_member_id` 用 `.default('atelier')`/`.default('me')` 让手写内容无需填 E5 字段但字段语义仍从 R1 起存在。

5. **`git credential` 子命令 stdin 必须用文件重定向**：PowerShell 管道把多行协议压成一行会报 `refusing to work with credential missing protocol field`。
