## 4. 发布 → 回滚 → 再发布演练（DoD ③）

演练目的不是「相信平台有回滚按钮」，而是**真的回滚一次并验证读路径不受影响**。

1. **记录基线**：记下当前部署的 commit SHA、部署 ID、时间；跑一次远端冒烟留档。
2. **制造一次可见变更**：用 `pnpm new:log "回滚演练"` 加一条 `build-log`（或改一处文案），
   `git push` → 等 CI 全绿 → 等平台部署完成 → 跑远端冒烟，确认新内容已在线上。
3. **回滚**：在平台部署历史里选上一份部署，点 Rollback / Redeploy → 等完成 →
   再跑 `pnpm deploy:smoke:remote https://真实域名`，确认：
   - 11 个核心页仍 200、单一 h1、正文可读；
   - RSS / JSON Feed / sitemap / Pagefind 仍可消费；
   - 首页零可执行脚本、图片仍带 srcset；
   - 刚才那条演练日志**不再出现**（证明确实回到了旧产物）。
4. **再发布**：把 HEAD 重新部署（或再 push 一条空提交触发），跑远端冒烟，确认演练日志回来。
5. **签字**：在本文件第 7 节表格填三次冒烟的时间、SHA、verdict 与操作人。未完成不勾 DoD ③。

> 因为「读路径全静态、动态层全部宕机也不影响读」，回滚期间表单/预约/分析可能短暂不可用，
> 但首页/作品/日志必须始终完整——这正是 M5 `test:nodynamic` 已经实测过的不变量。

## 5. 断网 / 禁用 JS 检查（DoD ②）

- 浏览器开 DevTools → Network 勾 Offline，或直接禁用 JavaScript 后刷新：
  首页、作品详情、日志详情、`/about` 的正文与导航仍应完整可读（纯 HTML + 一个 CSS 外链）。
- `/search` 是**唯一**依赖 JS 的页面（Pagefind 懒加载），断网/禁 JS 时它应显示降级说明，
  不影响其余页面——这是设计取舍，不是缺陷。
- 记录：浏览器、是否禁 JS、检查的 5 个 URL、结论。
