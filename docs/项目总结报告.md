## 1. 项目框架（Framework & Architecture）

### 1.1 立项原则

- **先自用、简单逻辑优先**（Q1）：不产品化，用「自己每天愿意写」验证价值后再谈演进。
- **范围冻结**：R1 明确不做 CMS、评论库、搜索服务、邮件队列、分析后端、登录体系、数据库、支付、多租户等（WON'T 清单）。
- **读路径全静态**（E1）：产物 `dist/` 为纯 HTML/CSS/静态资源，读路径上没有任何 fetch、数据库或会话。
- **一切可逆**（E12）：内容与代码同仓、无数据库、无迁移，任何步骤可 `git revert`。

### 1.2 技术栈与版本基线（精确锁定）

| 类别 | 选型 | 版本 | 说明 |
| --- | --- | --- | --- |
| 运行时 | Node | `>=22.23.4`（本机 v24.21.0） | `engines` 约束 |
| 包管理 | pnpm | `11.28.5` | `packageManager` 锁定，CI/CF 均按此版本 |
| 框架 | Astro | `7.4.11` | 静态输出，Rust 编译器 |
| 内容 | `@astrojs/mdx` / `zod` | `8.1.5` / `4.6.7` | Content Layer + Zod schema |
| SEO | `@astrojs/sitemap` / `@astrojs/rss` | `3.7.4` / `4.0.19` | sitemap、RSS、JSON Feed |
| 样式 | Tailwind 4 + `@tailwindcss/vite` | `4.3.5` | CSS-first，**无 `tailwind.config.js`** |
| 类型 | TypeScript | `6.0.3`（**强制锁定**） | `@astrojs/check` peer 仅收 `^5 || ^6`，禁止跟随 latest 7.x |
| 搜索 | pagefind | `1.6.0` | 构建后生成静态索引 |
| 测试 | vitest / Playwright / Lighthouse / axe-core | `5.1.0` / `1.65.0` / `13.6.0` / `4.14.0` | 单测 / E2E / 性能 / 无障碍 |

> 关键取舍：依赖版本在 `pnpm-lock.yaml` 中精确锁定、随仓库入库，禁止随意 `pnpm update`；`.npmrc` 已平台中立化（不写死 Windows 路径），保证 GitHub ubuntu-latest 可复现构建。

### 1.3 分层架构

```
内容源 src/content/**/*.{md,mdx,json}  （唯一内容源，明文，Git 版本史即备份）
        │  Content Layer + Zod 校验（src/content.config.ts）
        ▼
查询层 src/lib/          constants / queries / evidence / feeds / config
        │  isPublicProd 统一过滤；evidence 构建期解析证据链
        ▼
渲染层 src/pages/ + src/components/ + src/layouts/
        │  Astro 静态生成 → dist/
        ▼
构建钩子 astro:build:done → Pagefind 索引
        ▼
发布 public/_headers（严格 CSP） + git push → Cloudflare Pages 自动构建上线
```

**薄动态层（方案 A，零后端零密钥）**：订阅/联系走第三方表单端点或 `mailto:` 兜底，预约为 Cal.com 外链，分析用可选 Umami 单脚本；全部是 `PUBLIC_` 前缀的公开值，Vite 内联进静态产物，留空即降级、不留死链。R1.5 才考虑自建 Serverless（Resend），只需替换 `SubscribeForm.astro` 一个组件。

## 2. 设计（Design）

### 2.1 产品与信息架构

- **首屏信息预算（E6）**：身份 1 句、价值主张 1 句、精选作品 ≤3、主 CTA 1、次 CTA 1、导航 ≤5、社交外链 ≤3（仅页脚）；禁长段落、技能标签云、全量日志、动效轮播、第三方聊天挂件、cookie 横幅。相关常量集中在 `src/lib/constants.ts`（`NAV`、`CTA`、`FEATURED_LIMIT=3` 等）。
- **IA**：首页 `/`、`/products`（列表 + `[...id]` 详情）、`/log`（列表 + 详情）、`/capabilities`、`/about`、`/now`、`/uses`、`/contact`、`/subscribe`、`/privacy`、`/search`、`/rss.xml`、`/feed.json`。
- **转化漏斗**：主 CTA「聊聊你的项目」→ 联系页（表单 / mailto / Cal.com 外链），次 CTA「订阅更新」；北极星指标为每月合格线索数 MQL，**反指标为 PV**。

### 2.2 数据模型（Content Layer）

`src/content.config.ts` 定义 6 个集合：

| 集合 | loader | 关键字段 / 约束 |
| --- | --- | --- |
| products | `glob` | `tagline`、`stage`（idea/building/live/archived）、`featured`、`order`、`cover`（image）、`metrics` |
| log | `glob` | `kind`（6 种短类型）、`product_id`/`related_ids`（reference）、`reading_time` |
| capabilities | `glob` | `category`、`statement`、`evidence_ids`（**E4-a：非空且格式合法**） |
| cases | `glob` | `problem`/`solution`/`outcome`、`consent`（**E4-b：必须严格为 true**）、`consent_at` |
| pages | `glob` | `key`（about/now/uses/services/pricing） |
| profile | `file`（JSON） | 首屏身份/价值主张唯一数据源；联系方式分 `url`（外链）与 `value`（纯文本，如微信号不造死链） |

- 所有集合共享 `base` 字段（`workspace_id`/`owner_member_id` 恒定单值、`status`、`visibility`、`published_at` 等）。R1 无调度器，`status` 收敛为 `draft|published` 两级，避免 `scheduled` 静默发布陷阱。
- **构建期错误前置（E2）**：Zod schema + `astro check` + `astro build` 在 CI 串行，任一失败即阻断。

### 2.3 证据链设计（E4/E5）

Astro 7 的 `reference()` 只提供类型与自动补全，**不校验目标是否存在**。因此项目在 `src/lib/evidence.ts` 用 `resolveEvidenceList()` 于构建期解析每个 `evidence_id`（格式 `"<集合名>/<条目 id>"`，集合限 products/log/cases/capabilities/pages）：目标不存在即抛错中断构建。`scripts/verify-hard-rules.mjs` 用「写入违规内容 → 断言 build 非 0 → 清理 → 再断言恢复」的方式回归 E4-a/b/c 三条硬校验，确保「拦得住且不污染仓库」。

### 2.4 性能 / 隐私 / 安全设计

- **性能预算（E7）**：首屏 JS ≤50KB、LCP <1.5s（Slow 4G + CPU×4）、CLS <0.1、Lighthouse ≥95。
- **SEO**：`SITE_URL` 一处驱动 canonical / sitemap / OG / RSS / JSON Feed（默认 `https://website.85138175.xyz`，可由 `PUBLIC_SITE_URL` 覆盖）；`/search` 标 `noindex` 并从 sitemap 排除。
- **隐私（E8）**：事件不含明文 PII（仅 `anon_hash`）；订阅显式同意 + 来源留痕 + 一键退订；`privacy.astro` 的第三方脚本清单由当前构建实际配置生成，避免文案与产物不一致。
- **CSP（M6-e）**：`script-src` 仅 `'self'` + 构建期内联脚本 sha256 + `'wasm-unsafe-eval'`（Pagefind WASM 需要），**不放 `unsafe-inline`**；`style-src` 因 Pagefind UI 运行时内联样式明确放开 `'unsafe-inline'`（记录在案的取舍）。`/search` 是全站唯一内联可执行脚本，改动需重跑 `pnpm test:csp` 更新哈希。

## 3. 开发（Development）

### 3.1 写作流与内容工具

- `pnpm new:log "标题"`：2 分钟写一条创作日志（6 种短类型：build-log/decision/changelog/note/retro/now），支持非交互参数；这是对抗头号风险「弃更」（R-1）的核心工具。
- `pnpm new:product`：生成作品 `.mdx` 骨架，接管易错的 frontmatter（合法枚举/URL/日期校验、`order` 自动 +1、可选字段整行省略绝不写空值），**只生成文件、不自动 commit/push**。
- `pnpm changelog` / `export:all`：周报草稿与全量明文内容 + 订阅者 CSV 导出（内容主权 E3）。
- **MDX 坑（已修复并沉淀）**：正文裸写 `<https://…>` 会被 MDX 当 JSX 标签导致 build 失败，须用标准 Markdown 链接。

### 3.2 质量门禁体系

| 命令 | 覆盖 |
| --- | --- |
| `pnpm check` | astro check（TS + 模板），实测 0 errors / 0 warnings |
| `pnpm test` | check + test:rules（E4 三条）+ test:unit（vitest，README 记载 37 项） |
| `pnpm run quality` | **主门禁**：build → test:csp → test → verify:ci |
| `pnpm run quality:browser` | **浏览器门禁**：E2E（perf/search/lead/nodynamic/Playwright）→ Lighthouse → axe |
| `pnpm test:perf` | 真实浏览器 LCP/CLS/首屏 JS（Slow 4G + CPU×4） |
| `pnpm test:lead` / `test:nodynamic` | 表单字段与来源留痕 / 拔掉全部动态层后 5 页仍完整可读（不变量实测） |
| `pnpm verify:ci` | 检查质量链没漏脚本、ci.yml 完整、密钥未入库 |

- **零依赖 CDP 测试箱**（`scripts/cdp-harness.mjs`）：静态服务器 + Chrome headless + 真实响应头，被性能/搜索/线索/Lighthouse/axe 复用；`scripts/find-chrome.mjs` 跨平台定位 Chrome（`CHROME_PATH`/`PW_CHROME` 覆盖），本地与 CI 共用。
- **本地门禁与 CI 跑同一组脚本**，不搞「只在 CI 里绿」的断言；故意破 schema 必红（CI DoD）。
- **PowerShell 陷阱**：`cmd1 && cmd2` 非合法语句分隔符；执行多命令须逐条运行。

## 4. 部署（Deployment）

### 4.1 发布链路

```
写 .mdx ──► git push ──┬──► GitHub Actions（质检 4 job，不部署）
                        └──► Cloudflare Pages Git 集成（pnpm build → dist → 上线）
                                  └──► pnpm deploy:smoke:remote（消费端验真）
```

- **关键点**：Actions 与 Pages 由同一次 push **并行独立触发、互不打通**；CI 绿不代表部署停或产物对，发布后必须消费端冒烟验真。
- **GitHub Actions**（`.github/workflows/ci.yml`，ubuntu-latest）四段串行：`verify`（依赖+静态检查）→ `quality`（构建+硬规则，上传 dist）→ `browser`（真实浏览器回归）→ `audit`（密钥扫描）。**部署 job 刻意未加入**，发布交给 Pages Git 集成（零 API Token）。首个 push run `43395389553`（`b6d8632`）4/4 全绿。
- **Cloudflare Pages**：Build command `pnpm build`、output `dist`、环境变量 `PNPM_VERSION=11.28.5`（CF Build image v3 默认 pnpm 10.x，不认 `packageManager`，必须显式设）。

### 4.2 域名与 HTTPS

- 子域名 `website.85138175.xyz`，CNAME → 平台项目域 `website-1tq.pages.dev`（**注意不是 `website.pages.dev`**，后者 522）。
- NS 已在 Cloudflare 托管，证书已签发，实测 HTTPS 200（`Server: cloudflare`），两个域名（项目域与自定义域）远端冒烟均 PASS / failed:0。
- 顺序硬约束：必须先在 Pages 后台 Set up a domain，再加/自动建 CNAME；先手动加 CNAME 会 522。
- **CSP 顺序硬约束**：`PUBLIC_FORM_ENDPOINT`/`PUBLIC_UMAMI_*` 必须在 CF 构建**之前**设好，否则 CSP 不会放行相应外链，线上会被静默拦截。

### 4.3 部署冒烟

`pnpm deploy:smoke`（本地托管 dist）/ `pnpm deploy:smoke:remote <URL>`（线上）：以消费端视角验 11 个核心页 + feed + sitemap + Pagefind + srcset + 真 CSP 头。远端模式只记录 CSP 头不判失败（平台映射方式不同）。**它不验证**表单外部送达、DNS 邮件记录、国内可访问性、Lighthouse、axe——这些由人工表 / `quality:browser` 负责。

> 历史教训（已写入文档）：CF 曾报 "Deploy successful" 却发布仓库源码（因未配 build command/output），直到 `deploy:smoke:remote` 才暴露——**任何平台按钮的绿都不能替代消费端冒烟**。

## 5. 运维（Operations）

### 5.1 发布 → 回滚 → 再发布演练（M7-C，已闭环）

基线(11 条 feed) → 发布(12，哨兵日志上线) → 用户后台按**部署 ID 精确选中**基线回滚(11，哨兵消失) → 再发布(12，哨兵回来)，四轮 `deploy:smoke:remote` 全 PASS。要点：

- 回滚因「读路径全静态」无需回滚数据库/会话，等于重新指向上一份静态产物。
- 两个真实坑已记录：①演练期间文档回填会再触发含哨兵的部署，「选上一份」会点错，必须按部署 ID 选；②回滚后哨兵详情页**精确路径**仍返回旧 HTML（`Age`/`s-maxage=604800`），系旧部署边缘缓存残留（带随机 query 回源即证伪），至多 7 天自动消失或 Purge Everything。
- 回滚按钮由账号本人在 CF 后台点击（Git 集成、零 API Token 设计），脚本不冒充真人签字。

## 6. 结论
