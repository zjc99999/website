## 0. 维护约定（★ 必读，日久常新）

这是一份**需要持续维护的活文档**。约定如下，任何一次开发都请遵守：

1. **改命令即改手册**：凡新增 / 删除 / 重命名 `package.json` 里的 script，或改变某个脚本的参数、行为、输出，`docs/命令手册.md` 必须**同一个提交内**同步更新（第 2、3、4、5 节对应表格 + 第 9 节变更记录）。
2. **改配置即改手册**：`.env.example`、`astro.config.mjs`、`src/content.config.ts`、`.github/workflows/ci.yml`、Cloudflare 后台构建设置发生变化时，更新第 6 节。
3. **踩坑即补排错**：遇到新的构建失败 / CSP 漂移 / 部署异常并定位原因后，把「现象 → 根因 → 处理」写入第 8 节，避免重复踩坑。
4. **发布即留痕**：每次重要流程走通（尤其发布 / 回滚 / 演练），按第 7 节清单记录，并在第 9 节追加一行变更记录（日期 + 改了什么）。
5. **自检**：本手册的正确性由 `pnpm verify:ci` 间接保障（它会检查 CI 链没漏脚本、密钥未入库）；但**手册内容与源码的一致性靠人工遵守上述约定**——评审时若发现手册与源码不符，请当场修正。

> 配套文档：[能力提炼指南.md](能力提炼指南.md) —— 讲"什么值得成为能力、怎么提炼、怎么留证据"，是 §3.3 `new:capability` 的方法论前置。两文同步维护。

## 1. 环境与版本基线

| 项 | 要求 | 备注 |
| --- | --- | --- |
| Node | `>=22.23.4`（实测 `v24.21.0` 可用） | CI 用 Node 24；CF Build image v3 默认 22.23.4 |
| pnpm | `11.28.5`（`packageManager` 锁定） | 本机与 CF 后台都需这个版本；CF 须显式设 `PNPM_VERSION=11.28.5` |
| 包管理 | pnpm（frozen lockfile） | `pnpm install --frozen-lockfile`；禁止随意 `pnpm update` |
| TypeScript | **锁定 `6.0.3`** | `@astrojs/check` 的 peer 只接受 `^5 \|\| ^6`，升主版本会红 |
| 浏览器 | 系统 Chrome/Chromium | Playwright / Lighthouse / axe 复用；`CHROME_PATH` / `PW_CHROME` 可覆盖，安装时 `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` |

首次 / 换机器：
```bash
pnpm install --frozen-lockfile     # 装依赖（严格锁版本）
pnpm sync                          # 生成 .astro/ 类型（内容集合变更后也要跑）
```

> 平台/工具坑：本机 `npm` CLI 可能不存在，查包版本用 `node -e "fetch(...)"`；
> PowerShell 中 `cmd1 && cmd2` 不是合法分隔符，用 `;`。

## 2. 命令总表

按用途分组（完整权威清单见 `package.json`）。

### 2.1 开发 / 构建
| 命令 | 作用 |
| --- | --- |
| `pnpm dev` | 本地开发预览 `http://localhost:4321` |
| `pnpm build` | 产出 `dist/` 纯静态（含 pagefind 索引构建钩子） |
| `pnpm preview` | 预览构建产物 |
| `pnpm check` | `astro check`（TS 类型 + Astro 模板校验） |
| `pnpm sync` | 生成 `.astro/` 内容集合类型 |
| `pnpm serve` | 本地静态托管 `dist/`，并把 CSP 作为真实响应头发出（默认 4321） |

### 2.2 内容生产
| 命令 | 作用 |
| --- | --- |
| `pnpm new:log "标题"` | 交互式新建一条创作日志 |
| `pnpm new:product "标题"` | 交互式新建一个作品 `.mdx` |
| `pnpm new:capability "能力名"` | 半自动新建一条能力 `.md`（证据链需人工判断） |
| `pnpm changelog` | 汇总最近 7 天已发布日志 → `exports/` 周报草稿 |
| `pnpm export:all` | 导出全量明文内容 + 订阅者 CSV 模板 → `exports/` |
| `pnpm make:cover` | 重新生成示例占位封面（零依赖手写 PNG） |

### 2.3 质量门禁（本地）
| 命令 | 作用 |
| --- | --- |
| `pnpm test` | `check + test:rules + test:unit`（不含浏览器的全量回归） |
| `pnpm test:rules` | E4-a/b/c 三条硬校验的「故意破坏必红」回归 |
| `pnpm test:unit` | vitest 单测（常量/证据链/CSP 策略/新建工具） |
| `pnpm test:csp` | 从产物生成严格 CSP → `public/_headers` + `dist/_headers`（含漂移检测） |
| `pnpm test:perf` | 真实浏览器测 LCP/CLS/首屏 JS（Slow 4G + CPU×4） |
| `pnpm test:search` | 真实浏览器验证 Pagefind 站内搜索 |
| `pnpm test:lead` | 真实提交订阅/联系表单，校验字段与来源留痕 |
| `pnpm test:nodynamic` | 拔掉全部动态层后 5 个页面仍完整可读（不变量实测） |
| `pnpm test:pw` | Playwright 冒烟（首屏预算/导航/CTA/Feed/CSP 头） |
| `pnpm test:e2e` | `perf + search + lead + nodynamic + pw` |
| `pnpm test:lh` | Lighthouse 13 四类分数（门槛 95，实测 100/100/100/100） |
| `pnpm test:axe` | axe-core 5 个页面 a11y（实测 0 违规） |
| `pnpm verify:ci` | 检查 quality 链没漏脚本、`ci.yml` 完整、密钥未入库 |
| **`pnpm run quality`** | **★ 主门禁**：`build → test:csp → test → verify:ci` |
| **`pnpm run quality:browser`** | **★ 浏览器门禁**：`test:e2e → test:lh → test:axe` |

> ⚠️ **`pnpm ci` 是 pnpm 内建命令（clean-install）**，不要用它跑门禁；用 `pnpm run quality`。

### 2.4 部署 / 运维
| 命令 | 作用 |
| --- | --- |
| `pnpm deploy:smoke` | 部署前冒烟：本地托管 `dist/`，验核心页 + feed + sitemap + Pagefind + 真 CSP 头 |
| `pnpm deploy:smoke:remote <URL>` | 部署/回滚后对线上 URL 跑同一套消费端检查 |
| `pnpm pagefind` | 单独重建 `dist/pagefind` 搜索索引 |

## 3. 内容生产命令详解

三个 `new:*` 脚本纪律一致：**零依赖纯 Node、双模式**（TTY 交互 / 非交互）、只生成文件、**不自动 `git commit/push`**、可选字段无值就整行省略（写空值会被 YAML 解析成 `null` 使 build 失败）。

### 3.1 `pnpm new:log "标题"`
生成 `src/content/log/YYYY-MM-DD-slug.md`。
```bash
pnpm new:log "给首页做了 3 秒测试"                       # 交互选类型
pnpm new:log "标题" --kind=decision --summary="摘要"      # 非交互 / CI
pnpm new:log "标题" < /dev/null                          # 非交互，用默认值（pwsh 直接跑即非 TTY）
```
- `kind` 取值：`build-log | decision | changelog | note | retro | now`。
- 手工写也可以：frontmatter 至少 `title / summary / kind / status / published_at`；`workspace_id` / `owner_member_id` 有默认值可不写。字段定义见 `src/content.config.ts`。

### 3.2 `pnpm new:product "标题"`
生成 `src/content/products/<slug>.mdx`。
```bash
pnpm new:product "焕名"                                   # 交互补全
pnpm new:product "焕名" --stage=live --featured --slug=huanming --summary="一句话"
pnpm new:product "标题" < /dev/null                       # 非交互，用默认值
```
- 阶段字段 `stage`：`idea | building | live | archived`（默认 `building`）。
- `status` 只认 `draft | published`（**没有 `scheduled`**，R1 无调度器，写了是静默陷阱）。
- `featured: true` 才进首页「精选作品 ≤3」；`cover` 用相对内容文件的路径；可选字段没值整行省略。
- 完整参数与发布链路见 [使用指南-添加作品.md](使用指南-添加作品.md)。

### 3.3 `pnpm new:capability "能力名"`（★ 事后抽象，非自动生成）
生成 `src/content/capabilities/<slug>.md`。
```bash
pnpm new:capability "全栈交付"                            # 交互补全
pnpm new:capability "全栈交付" --category=工程 --statement="..." \
  --evidence=products/atelier,log/2026-11-12-scaffold-works
```
- **为什么要半自动**：能力是从作品 / 日志中**事后抽象**出的可复用证明（多对多）。新建作品时支撑它的日志还没写，自动生成只会得到空话 + 悬空证据（E4 构建期必失败）。故不在 `new:product` 时自动生成，而是在作品发布并写好创作记录后，用本命令补一条。
- E4 硬约束：`evidence_ids` 非空；id 格式 `"<集合名>/<id>"`（如 `products/atelier`），且**目标条目必须真实存在**，否则 build 失败。id 里不能再含 `/`。
- **先读方法论再动手**：提炼什么值得写成能力、statement 怎么写、证据怎么选，见 [能力提炼指南.md](能力提炼指南.md)（本命令的"判断力前置"；命令只负责生成合规骨架）。

### 3.4 汇总 / 导出
```bash
pnpm changelog              # 最近 7 天已发布日志 → exports/ 周报草稿
pnpm changelog --days=30    # 最近 30 天
pnpm changelog --all        # 全部已发布日志
pnpm export:all             # 全量明文内容 + 订阅者 CSV 模板 → exports/
```

## 4. 构建与质量门禁（★ 发布前必过）

两条门禁链与 `.github/workflows/ci.yml` 跑的是**同一组脚本**，CI 不另搞一套断言：

```bash
pnpm run quality           # build → test:csp → test(check + E4 + 单测) → verify:ci
pnpm run quality:browser   # test:e2e → test:lh → test:axe（需系统 Chrome）
```

CI 四段串行（`ubuntu-latest`，`verify → quality → browser → audit`），前一段红就不进下一段：

| 段 | 跑什么 | 关键点 |
| --- | --- | --- |
| 1/4 verify | `pnpm install --frozen-lockfile` + `pnpm test` | 类型 + 硬规则 + 单测 |
| 2/4 quality | `pnpm run quality` | 上传 `dist` 供下游 job |
| 3/4 browser | 取回 `dist` + `pnpm run quality:browser` | 用 `find-chrome.mjs` 定位系统 Chrome |
| 4/4 audit | `node scripts/secret-scan.mjs` | 密钥扫描（与本地 `verify:ci` 同一引擎） |

> **部署 job 刻意未加入 CI**：发布交给 Cloudflare Pages 的 Git 集成（零 API Token）。CI 只负责「产物可交付」。

关键设计（改动前务必理解）：
- **CSP 由产物生成**：`test:csp` 扫描产物 HTML 里的外链推导 `_headers`，改 `/search` 内联脚本后必须重跑更新哈希，否则 CSP 拦掉它。
- **故意破 schema 必红**：`test:rules` 写入违规内容 → 断言 build 非 0 → 清理 → 再断言恢复 0。把违规内容提交进仓库，CI 必然红。
- **Markdown 代码块不用 Shiki 内联高亮**：`astro.config.mjs` 设 `markdown.syntaxHighlight: false`，代码块退化为 `<pre><code>` 由 CSS 着色——因为 Shiki 默认输出的内联 `style=` 会违反「产物零内联 style」的 CSP 门禁（见第 8 节）。

## 5. 部署与运维命令

### 5.1 冒烟检查（消费端视角）
```bash
pnpm deploy:smoke                                   # 本地托管 dist/，验证产物能否被消费
pnpm deploy:smoke:remote https://website.85138175.xyz  # 线上自定义域
pnpm deploy:smoke:remote https://website-1tq.pages.dev # 平台默认域
# 或：DEPLOY_URL=https://真实域名 pnpm deploy:smoke
```
- 检查项：HTTP 状态、每页单一 h1、canonical、RSS 2.0 / JSON Feed 1.1 / sitemap / Pagefind、首页零可执行脚本、严格 CSP 头、图片 `srcset`、隐私/联系/订阅页可达。输出 `@@SMOKE@@ verdict:PASS/FAIL failed:N`，任一失败退出码 1。
- **诚实边界**：不验证表单外部送达、DNS/邮件记录、国内可访问性、Lighthouse、axe（这些靠第 6 节人工表 / `quality:browser`）。
- ⚠️ **平台按钮绿 ≠ 线上产物正确**：CF 曾报 "Deploy successful" 却发布仓库源码（未配 build/output），是 `deploy:smoke:remote` 暴露的。任何部署/回滚后都要跑远端冒烟。

### 5.2 发布链路
`git push origin main` → GitHub Actions 四段全绿 → CF Pages Git 集成自动构建部署 → `pnpm deploy:smoke:remote` 确认。发布由账号本人操作，零 API Token。

### 5.3 回滚
在 **CF 后台 → Workers & Pages → 项目 `website` → Deployments → All deployments**，**按部署 ID 精确选中基线那份** → Rollback → 等完成 → `pnpm deploy:smoke:remote` 确认内容回到旧版。
> 坑：文档回填也会触发含哨兵的新部署，「选上一份」会点错；回滚后旧详情页精确路径可能因边缘缓存（`Age` / `s-maxage=604800`）短暂仍返旧 HTML，带随机 query 回源即证伪。详见 [部署与回滚演练.md](部署与回滚演练.md) §4。

## 6. 配置清单

### 6.1 环境变量（`.env.example` → `.env`，密钥绝不入库）
全部为 `PUBLIC_` **公开值**，由 Vite 内联进静态产物；留空即不启用、不留死链。

| 变量 | 留空行为 | 当前值/默认 |
| --- | --- | --- |
| `PUBLIC_SITE_URL` | 用代码默认 | `https://website.85138175.xyz` |
| `PUBLIC_FORM_ENDPOINT` | 表单整块降级为 `mailto:` | 待配（配后需邮件送达实测） |
| `PUBLIC_CONTACT_EMAIL` | 邮件兜底收件人 | `zjc_9999@163.com` |
| `PUBLIC_CAL_URL` | 不渲染预约入口 | `https://cal.com/zjc-9999/30min` |
| `PUBLIC_UMAMI_SCRIPT_URL` + `PUBLIC_UMAMI_WEBSITE_ID` | **两项必须同时配**才加载；留空则零客户端 JS | 空 |
| `RESEND_API_KEY` | 仅方案 B / R1.5 用，R1 方案 A 不需要 | 不设 |

> ⚠️ **CSP 顺序硬约束**：`PUBLIC_FORM_ENDPOINT` / `PUBLIC_UMAMI_*` 必须在 **build 之前**设好。先构建后补，产物里没有外链，CSP 就不会放行，线上会被静默拦截。

### 6.2 代码 / 平台配置
| 文件 / 位置 | 作用 |
| --- | --- |
| `astro.config.mjs` | `site` = `PUBLIC_SITE_URL \|\| 默认`；集成 mdx + sitemap（过滤 `/search`）+ atelierPagefind；`markdown.syntaxHighlight: false`；Tailwind v4 CSS-first |
| `src/content.config.ts` | 6 个内容集合与 Zod schema（products/log/capabilities/cases/pages glob + profile file）；E4/E5 硬约束 |
| `src/lib/constants.ts` | NAV/CTA/FEATURED_LIMIT/RECENT_LOG_LIMIT/CAPABILITY_LIMIT/SOCIAL_LIMIT（首屏预算 E6） |
| `public/_headers` | 由 `test:csp` 生成的严格 CSP + 安全响应头（入库，平台直接消费） |
| `.github/workflows/ci.yml` | 四段串行门禁（见第 4 节） |
| `.github/dependabot.yml` | 依赖更新只提 PR、禁止自动合并；忽略 TS 主版本 |
| CF 后台构建设置 | Build command `pnpm build`；output `dist`；`PNPM_VERSION=11.28.5` |
| CF 自定义域名 | CNAME `website → website-1tq.pages.dev`（须先在 Pages 后台 Set up domain，否则 522） |

## 7. 常见工作流清单

**日常写一条日志**
```bash
pnpm new:log "标题"        # 或手写 .md
# 填正文 → pnpm run quality → git add/commit/push → 远端冒烟
```

**新增一个作品**
```bash
pnpm new:product "标题"    # 填正文/封面 → quality → push
# 发布并写好创作记录后，再 pnpm new:capability 补一条能力（evidence 指向作品+日志）
```

```bash
pnpm new:capability "能力名" --category=... --statement=... --evidence=products/xxx,log/yyy
```

```bash
pnpm run quality && pnpm run quality:browser   # 本地门禁（pwsh 用 ; 不用 &&）

```

## 8. 排错手册（现象 → 根因 → 处理）

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| `test:csp` 失败，报 `style=` 属性 | Markdown 代码块被 Shiki 默认高亮，输出 `<pre style=...>` / `<span style=...>`，违反产物零内联 style | 保持 `astro.config.mjs` 的 `markdown.syntaxHighlight: false`，代码块由 `.prose pre/code` 着色；**不要放宽 csp-check 门禁** |
| `/search` 在 CSP 下不工作 | 改了唯一内联脚本但没更新哈希 | 重跑 `pnpm test:csp` 更新 `public/_headers` 哈希 |
| build 报 evidence 不存在 | `evidence_ids` 指向的条目不存在 / id 含非法 `/` | 确认 `<集合>/<id>` 格式且目标文件真实存在；重跑 `pnpm check` |
| build 报 YAML null | frontmatter 写了 `url:` 等空值 | 可选字段**整行省略** |
| 线上表单/分析被静默拦截 | 先 build 后补 `PUBLIC_FORM_ENDPOINT` / `PUBLIC_UMAMI_*`，CSP 未放行外链 | 在 CF 后台构建**前**设好变量，重新部署 |
| CF "Deploy successful" 但线上是源码 | 未配 Build command / output，CF 把仓库根当静态站上传 | CF 后台设 `pnpm build` + `dist` + `PNPM_VERSION`，用空提交重触发 |
| 自定义域返回 522 | 先加了 CNAME 但没在 Pages 后台关联域名 | 先在 Pages「Custom domains → Set up a domain」，再让 CF 自动建 CNAME |
| 回滚后旧日志页仍可访问 | 旧部署详情页的边缘缓存残留（`Age`/`s-maxage=604800`） | 带随机 query 回源证伪；至多 7 天自动消失，或 CF Purge Everything |
| push 被 403 | Windows 凭据管理器缓存了错误账号 `zjc9999`（少一个 9） | `cmdkey /delete:git:https://github.com` 清缓存，用 `zjc99999` 重新认证 |
| `pnpm update` 后 check 红 | 把 TypeScript 升出 `6.0.3`，`@astrojs/check` peer 不匹配 | 锁回 `6.0.3` |
