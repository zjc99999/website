# 使用指南：添加一个作品（new:product）

> 面向「站点已经上线，现在要补一个之前做好的项目」这一件事。
> 工具：`scripts/new-product.mjs`（`pnpm new:product`）。字段定义以 `src/content.config.ts`
> 的 `products` schema 为准（schema 即文档），构建期 Zod 校验兜底。

## 0. 先把两个概念摆正

你的理解「照模板新建一个 `.mdx` → `git` 提交 → 自动上线」**基本正确**，只差一处措辞：

- ✅ 一个 `.mdx` 文件 = 一个作品。文件里 frontmatter 装全部元数据、正文装介绍，不需要在任何地方「注册」。
- ✅ 改仓库明文文件 → `git commit` + `git push` → 站点自动更新。平时**不用**去 GitHub / Cloudflare 网页点任何东西。
- ⚠️ 「Actions 自动执行并**打通 Cloudflare**」不准确。`.github/workflows/ci.yml:22-23` 明写部署 job 刻意未加入：
  - **GitHub Actions** 只做质检（verify → quality → browser → audit 四个 job），不负责部署；
  - **Cloudflare Pages** 通过自己的 GitHub App / Git 集成独立触发 `pnpm build` 并发布 `dist/`。
  - 两者由**同一次 push** 并行触发、互不打通：CI 红了不代表部署会停（部署看的是它自己那次构建是否成功），
    所以发布后仍要用消费端冒烟验真，而不是看 CI 绿没绿。

```
你写 .mdx ──► git push ──┬──► GitHub Actions（质检，4 job，几分钟）
                          └──► Cloudflare Pages（pnpm build → dist → 上线）
                                        │
                                        └──► pnpm deploy:smoke:remote https://website.85138175.xyz（验真）
```

## 1. 用工具生成（推荐）

工具只做**生成骨架**，把最容易写错的 frontmatter 那一半接管掉；它**不会**替你
`git commit` / `git push`（避免把没填完正文的半成品直接推上线）。

### 交互式（在终端里敲，按提示填）

```bash
pnpm new:product
```

会依次问：标题、tagline（卡片上那一句）、摘要、阶段（1-4，已完成的项目选 `3 = live`）、
是否进首页精选、URL 短名（建议用英文短名，回车则用标题生成）。

### 非交互式 / 脚本 / CI（一条命令带齐参数）

```bash
pnpm new:product "焕名 文件批量重命名" \
  --slug=huanming \
  --tagline="给文件批量改名的小工具" \
  --summary="Windows 下批量重命名的桌面工具，零依赖、可离线" \
  --stage=live \
  --featured \
  --url=https://example.com/huanming \
  --repo_url=https://github.com/me/huanming \
  --launch_date=2025-08-01 \
  --tags="桌面工具,Windows,效率" \
  --order=2
```

生成 `src/content/products/huanming.mdx`，终端会打印：

```
✓ 已生成：src/content/products/huanming.mdx
  线上路径：/products/huanming/
  阶段：live（已上线）  featured=true  order=2  status=published
```

> 同名文件已存在时自动加 `-2`（不会覆盖）。`order` 不给时自动取现有所有作品 `order` 最大值 +1
> （新作品排最后）；首页精选按 `order` 升序取前 3 个。

### 全部参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 第一个位置词 / `--title=` | 必填 | 作品标题；非交互模式缺标题直接报错退出 |
| `--slug=` | 由标题生成 | URL 短名；保留中文、小写英文数字，其余压成连字符，最长 60 |
| `--tagline=` | = 标题 | 卡片上那一句 |
| `--summary=` | = tagline | 摘要，进 RSS / JSON Feed |
| `--stage=` | `building` | `idea` / `building` / `live` / `archived`；**已完成的项目选 `live`** |
| `--featured` | 不带= false | 裸标志，带它就进首页「精选作品 ≤3」 |
| `--status=` | `published` | `draft`（本地 dev 可见、生产产物里完全不存在）/ `published` |
| `--visibility=` | `public` | `public` / `unlisted` / `private` |
| `--url=` | 省略 | 产品外链，必须完整 `http(s)://`，卡片/详情页出「访问站点 ↗」 |
| `--repo_url=` | 省略 | 源码外链，必须完整 `http(s)://`，出「源码 ↗」 |
| `--launch_date=` | 省略 | `YYYY-MM-DD`，详情页显示「… 上线」 |
| `--cover=` | 省略 | 相对**内容文件**的路径，如 `../../assets/xxx.png`；必须以 `../` 或 `./` 开头 |
| `--published_at=` | 今天 | `YYYY-MM-DD` |
| `--updated_at=` | 省略 | `YYYY-MM-DD` |
| `--locale=` | `zh-CN` | `zh-CN` / `en` |
| `--tags=` | `[]` | 英文逗号分隔，如 `桌面工具,Windows` |
| `--order=` | 现有 max+1 | 非负整数，决定列表与首页精选顺序 |
| `--seo.*` / `--metrics.*` | 省略 | 暂不由工具生成，按文末「可选字段」手工补进 frontmatter |

**前置校验**（坏值在写文件前就拦住，不留给 build 猜）：枚举值、日期格式、URL 协议、
cover 相对路径、order 非负整数、标题/tagline/summary 非空。

## 2. 生成之后要做的两件事

### ① 填正文

工具给出三段式骨架（`.mdx`，用 `{/* */}` 注释，**不能**写 HTML 注释 `<!-- -->`，
否则 MDX 编译直接失败——这是真实 build 探针抓到并锁进单测的坑）：

```
## 这是什么      ← 一句话说清它是什么、给谁用
## 为什么做      ← 当时要解决什么问题
## 设计上的取舍  ← 做了什么、放弃了什么
```

注释里还列了全部可选字段与「写 `product_id: <slug>` 把创作日志挂到本作品详情页」的提示，
照着补即可。**可选字段没值就整行删掉**，千万别写 `url:` 这种空值——YAML 会解析成
`null`，Zod 报 `Expected type "string", received "object"`，build 必红。

### ② 本地看一眼（可选但推荐）

```bash
pnpm dev          # http://localhost:4321/products/<slug>/
pnpm run quality  # build + CSP + check + E4 三条 + 37 个单测 + CI 链自检
```

`quality` 里的真实 `astro build` 会用 Zod 校验这个新文件；不合规就地报错，不会污染线上。

## 3. 发布与验真

```bash
git add src/content/products/<slug>.mdx
git commit -m "content: 添加作品 <标题>"
git push origin main
```

然后等两件事（约 1~2 分钟）：

1. GitHub Actions 四个 job 全绿（只说明「产物可交付」）；
2. Cloudflare Pages 那次 `pnpm build` 成功、`dist/` 发布完成。

最后**用消费端验真**，别只看 CI：

```bash
pnpm deploy:smoke:remote https://website.85138175.xyz
```

它会检查 11 个核心页 200、RSS / JSON Feed（新作品会进 feed）、sitemap、Pagefind、
真 CSP 响应头、图片 `srcset`、转化与隐私页可达。要确认新作品本身上线，
再直接打开 `https://website.85138175.xyz/products/<slug>/`，
或取回 `https://website.85138175.xyz/feed.json` 搜一下 `<slug>` 是否出现在 items 里。

## 4. 一个文件会自动出现在哪里

| 条件 | 出现位置 |
| --- | --- |
| 无条件 | `/products/` 列表、详情页 `/products/<slug>/`、RSS 2.0、JSON Feed、sitemap、Pagefind 搜索 |
| `featured: true` | 首页「精选作品」（≤3，按 `order` 升序） |
| 某条日志写 `product_id: <slug>` | 该作品详情页底部「这个作品的创作记录」 |
| `status: draft` | 仅本地 `pnpm dev` 可见，生产产物里完全不存在 |
| `stage: archived` | 仍展示，标签为「已归档」 |

> 能力（`capabilities`）必须挂 `evidence_ids` 且目标真实存在；案例（`cases`）必须
> `consent: true`。这两条是构建期硬校验 E4，指向不存在的证据或未授权客户信息会让 build 失败。

## 5. 常见错误对照

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| `Expected type "string", received "object"` | 可选字段写了空值（如 `url:`） | 整行删掉，或填完整值 |
| `Unknown stage` / build 红 | 把生命周期写进了 `status` | 生命周期用 `stage`；`status` 只认 `draft`/`published` |
| `mdx-jsx:unexpected-character`（`Unexpected character !`） | `.mdx` 里用了 `<!-- -->` | 改用 `{/* ... */}` |
| 首页看不到新作品 | 没带 `--featured`，或已有 3 个精选且 `order` 更大 | 带 `--featured` 且按需给更小的 `--order` |
| `cover` 找不到 / 不生成 WebP | 写了绝对路径或 `import sharp` | 用 `../../assets/xxx.png` 相对路径，交给 Astro `image()` |
| 推了但线上没变 | 只看了 CI 绿 / 部署那次构建失败 / CDN 缓存 | 查 CF 部署那次构建日志，再用 `deploy:smoke:remote` 验真 |
| 本地可见、线上没有 | `status: draft` | 改成 `published` 再 push |

## 6. 完整示例（一个已完成项目）

```bash
pnpm new:product "焕名 文件批量重命名" \
  --slug=huanming --stage=live --featured \
  --tagline="给一堆文件一次改好名字" \
  --summary="Windows 桌面批量重命名工具，支持正则与预览，零依赖可离线" \
  --url=https://example.com/huanming \
  --launch_date=2025-08-01 --tags="桌面工具,Windows,效率"
```

打开生成的 `src/content/products/huanming.mdx`，三段正文填完、可选字段按注释补齐，
然后 `git add` → `git commit` → `git push` → `pnpm deploy:smoke:remote https://website.85138175.xyz`。
